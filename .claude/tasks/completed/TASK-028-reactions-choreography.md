### Decisions + disclosures (doc-cited)

1. **Exhaustiveness mechanism**: `ReactionID` is String-backed in MomoCore (INV-11, catalog-owned), so the build-error guarantee is realized as internal `MomoReactionKey: String, CaseIterable` (failable init from `ReactionID`) + a literal 21-string census test. 4. **Play bound**: worst case 2.4 (invite) + 16.0 (follow deadline) + 4.0 (payoff) = 22.4 s ≤ 30 ALWAYS. 6. **Moment supersession**: a newer `momentRequest` replaces a running moment with no `momentFinished` for the displaced one (no cancel report kind exists; the deferred request supersedes). Persistent identical requests dedupe on the transition.
7. **Report latency**: completion reports materialize at the first fold past the end instant (at: the end instant itself), never on wall-clock time — engine tolerance covers the fold latency; pause discipline guarantees nothing completes while hidden.
8. **Rule 3 window semantics**: fixed-start window (opens at the first arrival; 5+ past the single coalesced beat are absorbed; expiry REPLACES, not extends).
9. **L3-during-L2 renders additively** (fix round: the glance-up gate is ACTIVITY + TOUCH-FAMILY, MAJOR-2 + NOTE-7): an arriving L3 does not disturb a running settle/play/meal slot (only an L2 CHANGE preempts L3s per Rule 2).
