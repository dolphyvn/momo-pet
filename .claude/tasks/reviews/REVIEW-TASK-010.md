### NITPICK-2 — ImportWhitelistScan docstring overclaims "never miss a real import"

`ImportWhitelistScan.swift:74-76` ("the conservative parser can only over-report, never miss a real import") and the echo at `TASK-010-test-harness-scans.md:63`. Probe P1 empirically disproves the absolute claim in a narrow case: `let s = "hello"; import AppKit` on a statement-led single line is **missed**, because the line tokenizer only recognizes lines whose first token is `import` (an unterminated string literal would likewise blind the rest of a file — though such a file cannot compile). Every realistic accidental construct — imports at line start, which is effectively all real-world Swift — is caught, and exploiting the gap requires deliberately hostile code that would violate §25 on its own. **Suggested fix**: a one-line wording change in the docstring (and optionally the task-file echo), e.g. "no realistic accidental import escapes; a same-line `; import X` after a statement is outside the model" — no code change required. (Related observation, verified benign: `@_exported import` is handled in code but has no repo fixture; probe P1 proved it is caught.)
