## Findings

### MAJOR — none.

### MINOR-1 — A zero-elapsed `wakeFinished` voids an accepted (and counted) mid-waking nap: `HandshakeMachine.complete(kind:)` unconditionally clears `activity`

`Sources/MomoCore/HandshakeMachine.swift:132-140` — every `complete(…)` transition rebuilds `PetState` with `activity: nil`. Judgment call 10 (contract-lettered via Req 9: band-gated interactions apply during `.waking`) lets a Drowsy pet start a nap while `.waking` (`InteractionSemantics.applyNap`, `Tests/MomoCoreTests/InteractionResponseTests` has no waking-nap cell; the path is reachable through `reduce`: wake token minted → nap intent applies → `activity = .napping`, `careCount` +1). When the character's `wakeFinished` report arrives with **zero elapsed**, `reduce`'s fold is skipped (`from >= to`), so `HandshakeMachine.complete(kind: .wake, from: .waking, to: .awake, …)` has the last word: the nap is erased without `FoldRules.napRestoreEnergy`, while the care count stands. With any positive elapsed the fold completes the nap first (nap-completion at fold end, `TimeFold.swift:207-213`), so the hole is a zero-width instant — but a counted care event silently not happening is an integrity gap, and `ManualEngineClock` fixtures (and adversarial/synced delivery) can hit zero elapsed. Probe evidence (method 8, PROBE 1, verbatim): `energy after wakeFinished: 30.0 (nap would be 50)`, `activity: nil`, count 1.
**Not warm-breaking** (no mood loss, pet simply stays awake) and conservative — hence MINOR, not MAJOR. **Suggested one-line disposition** (mechanical, safe — `.settle` paths always carry `activity == nil`): have `complete(…)` clear the activity only for the settle kinds and preserve it for `.wake` (`activity: kind == .wake ? state.state.activity : nil`), or add nap to the waking-decline set beside play/tuck-in. Either closes the void; recording it as an EPIC follow-up instead is defensible given zero production reachability — the orchestrator chooses, but it must be dispositioned either way.
