## Findings

### MAJOR-1 — Leakage suite does not hold "for every case": a new payload-bearing band case passes the entire suite (Probe D)
- **Evidence:** `NoNumericLeakageTests.swift:57,60,63,70,73,76` enumerate the cases explicitly (`[MoodBand.joyful, .content, .wistful, .low]` etc.), but the file header (lines 12–14, 28–31) claims coverage "**for every case** of `MoodBand`, `EnergyBand`, `BondStage`" and non-vacuity per mutation class. Probe D added `case historic(Int)` to `MoodBand`: compilation succeeded (no exhaustive switch over band enums exists anywhere — verified by grep; the enums are not `CaseIterable`), and the **full 79-test suite passed green** with the numeric-payload case present. A maintainer can add a leakage-bearing case and the "mechanically checked" FR-9 guarantee silently rots — precisely the failure mode this task exists to prevent. The case set of the band/stage enums is pinned nowhere else in the repo.
- **Suggested fix (test-file only, honors TASK-013's constraint):** in `NoNumericLeakageTests`, add a default-free exhaustive-switch name helper per type (the existing INV-8 pattern, `DomainInvariantsTests.swift:188–199`), e.g. `prdCaseName(of:)` for each of `MoodBand`/`EnergyBand`/`BondStage`, asserted to equal the PRD case-name sets. Adding/removing any band/stage case then **breaks compilation of the leakage test itself**, converting the claimed "every case" into a compile-time fact. ~20 lines; no source change; no new dependency.

### MINOR-1 — Reflection method's computed-member/subscript/extension blind spot is real (Probe E) but undocumented
- **Evidence:** computed `var bondStageOrdinal: Int` on `CharacterDisplayState` passed the suite (Mirror reflects stored properties only). The header documents the method as field inventories + type shape, and Requirement 4's operative wording is "no public raw numeric band **fields**" — so this is inside the documented scope and today the module has zero computed members (verified: `var` scan over `Sources/MomoCore/` → empty). Adjudicated MINOR rather than MAJOR on that claimed-scope analysis; noted plainly because a blanket reading of the probe instruction could rate it MAJOR — the orchestrator may overrule.
- **Suggested fix:** one header sentence in `NoNumericLeakageTests.swift` documenting the limitation (fields only; computed members/subscripts/extensions are invisible to this method), plus a standing note (status.md Known Issues or the EPIC-004 review checklist) so engine-era additions of numeric computed accessors on read-models get caught by review.
